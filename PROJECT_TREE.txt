Database Schema
===============

Tables (Multi-tenant with hospital_id):
------

Core:
  - users (phno, username, password, email, role, hospital_id)
  - hospitals (id, name, code, created_at)

Clinical:
  - patients (id, hospital_id, phone, name, dob, assigned_doctor_phno)
  - appointments (id, patient_id, doctor_phno, hospital_id, status, slot_id)
  - consultations (id, appointment_id, patient_id, doctor_phno, hospital_id, status, type)
  - prescriptions (id, consultation_id, doctor_phno, hospital_id)
  - doctor_slots (id, hospital_id, doctor_phno, day_of_week, start_time, end_time)

Billing & Payments:
  - charge_items (id, hospital_id, category, name, default_price)
  - billing (id, consultation_id, hospital_id, status)
  - payment_orders (id, charge_id, hospital_id, order_id, amount)

Pharmacy:
  - pharmacy_records (id, prescription_id, hospital_id, status, dispensed_by)

OTP:
  - otp_tokens (id, email, code, purpose, created_at, expires_at)


Key Features
============

✓ Multi-tenant architecture (shared DB, row-level security)
✓ JWT-based authentication (asymmetric signing RS256)
✓ Role-based access control (ADMIN, PATIENT)
✓ Doctor schedule management (slots, availability)
✓ Patient appointment booking (registered & walk-in)
✓ Consultation workflow (DRAFT → FINALIZED)
✓ Prescription management (drugs, dosage, quantity)
✓ Charge master catalog (editable fees, medicines, tests)
✓ Auto-billing (based on finalized consultation)
✓ Payment processing (Razorpay integration)
✓ Pharmacy dispensing records
✓ Dashboard analytics (admin & patient)
✓ OTP-based email verification
✓ Responsive UI (desktop & mobile)
✓ HIPAA-aligned security baseline

Getting Started
===============

1. Local Dev (5 min):
   git clone <repo>
  cd healthboxd
   docker-compose up -d db
   cd backend && ./mvnw spring-boot:run
   cd frontend && npm install && npm run dev

2. Read Documentation:
   - QUICKSTART.md (5-minute setup)
   - README.md (architecture & API)
   - DEPLOYMENT.md (production guide)
   - DEPLOYMENT_CHECKLIST.md (pre-launch)

3. Deploy:
   - Follow DEPLOYMENT.md for your chosen platform
   - Use DEPLOYMENT_CHECKLIST.md before going live
